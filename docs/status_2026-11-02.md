# Status 2026-11-02: first real-robot grasps in the pinching feasibility test

> Paths in this record are those of its date; see [docs/refactor_2026-11.md](refactor_2026-11.md) for the current ones.

Facts copied from the working status note of 2 November 2026 (kept outside this repository; sections "Results so far
(P20-Cg, offline)" and "Robot result 2026-11-02") and from the data owner, so that the technical report can cite them
from a file in the repository. The setup, data and test sets are described in [status_2026-11-01.md](status_2026-11-01.md).

**What this is and is not.** Successful grasps were observed in real-robot trials on 2 November; **trials were not
counted**, so there is **no success rate**. The two runs below are the ones the data owner identified as successful;
they are examples, not a sample.

## Task

Egocentric (HandUMI) demonstrations → reBot: **pinch one sleeve with the left hand.** The right arm is idle in all data.
In the runs of 2 November both arms were under policy control; the right arm stayed at its start pose and its jaw closed.

## Checkpoint

The DiT fine-tune from the E1000 checkpoint (step 227795) on the 197-demo Cg set, with train-time image augmentation
(run `DITFT-E1000F227795-U200CG-S05-B64ACC4-BCE-GSM-AUG-E500-NOCLIP`), checkpoint saved at **50 epochs (step 048564)**.
Other checkpoints (the 25-epoch one, step 024282, and an earlier flattening fine-tune) were also run that day; the
successful runs below used the 50-epoch checkpoint.

## Offline results (P20, Cg; 19 held-out demos)

`val_score_mm`: the mean, over k = 16 and k = 32 and over the left and right arm, of the translation deviation in mm
(position only). Lower is better. It measures agreement with held-out human motion, not task success.

| checkpoint | `val_score_mm` |
|---|---|
| E1000, step 227795 (53 demos; baseline) | 19.89 |
| 197-demo fine-tune, 25 epochs (step 024282) | 17.29 |
| 197-demo fine-tune, 50 epochs (step 048564) | 18.89 |

The 50-epoch checkpoint scores worse offline than the 25-epoch one (18.89 vs 17.29 mm) but is the one that grasped on
the robot; the offline score did not pick the robot checkpoint.

## Robot runs of 2 November (observation, trials not counted)

* Runs identified by the data owner as successful: `dit_go_20261102_113704` (started 11:37:04, 21 plan cycles, 28.0 s)
  and `dit_go_20261102_114857` (started 11:48:57, 28 plan cycles, 37.7 s); each run folder holds `summary.json`,
  `log.npz` and the composed UI video (one frame per plan cycle). Both were ended by the operator from the UI (stop / hold).
* Deploy settings: DiT policy, **32 steps committed per plan**, **speed 1.0**, real-time-chunking look-ahead **off**,
  **DDIM, 10 sampling steps**, per-arm table-height calibration **on**, soft stop.
* Observed behaviour: the left arm approaches the sleeve end with the jaw open, closes on the sleeve and drags it.
* **Known behaviour after a miss:** the policy grasps somewhere else instead of retrying the same grasp. The data contain
  no recovery demonstrations, so post-failure states are out of distribution. A retry is done by sending the arms back
  to START and pressing GO again. The data fix is to record recovery demonstrations.

## Hardware and deploy changes on 2 November

* **Arm sides swapped after re-cabling.** The bridge selects each arm by its USB location ID; after re-cabling the two
  locations had changed, so the launch configuration was corrected (configuration, not code). The robot wrist cameras
  had also moved ports and were re-assigned.
* **Left jaw slack.** The left jaw's zero is still correct (closed by hand it reads about −1°, open about −218°), but it
  has mechanical slack, so a close to 0° no longer pinched firmly. The bridge now closes it **25° past zero**
  (`MIT_GRIP_CLOSE_DEG_LEFT=25`), with the extra squeeze ramped in over the **last 30°** of travel only, so open
  commands keep their physical angle; a squeezed jaw is reported as 0° (closed), so a stop or READY no longer re-sends
  a partly open jaw (`scripts/deploy/robot_bridge/robot_service_mit.py`).
* **START closes both jaws.** A parked (torque-off) jaw relaxes open; the START move re-sent that observed jaw, while
  every training episode starts closed. The START move now commands both jaws closed
  (`src/garment_pipeline/eval_deploy/tagrig_deploy/start_pose.py`).
* **One wrist-camera stall.** The right robot wrist camera once delivered empty frames mid-run and could not be
  reopened; restarting the deploy UI fixed it.
