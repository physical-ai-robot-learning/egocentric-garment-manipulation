Facts copied from the working status note of 1 November 2026 (kept outside this repository), so that the technical
report can cite them from a file in the repository. Nothing here is a counted robot result: **no counted robot trial
of the pinching policy has been run yet**; the only robot runs are the qualitative runs of 1 November listed below. Names in `code font` are dataset / run names on the original machines.

## Goal

A first feasibility test of egocentric (HandUMI) demonstrations → reBot: **pinch ONE sleeve with the LEFT hand.**
The right arm is idle in all data (its jaw stays closed); the policy is deployed with the left arm only.

## Data

All sets are 0.5× time-stretched ("S05"), built with label kind **F** (`tag_rig_unsplit.py --label fused`: fused human
jaw-tip pose in reBot gripper axes, 0.25 s smoothing, before IK, no table lift or clamp) from the **Cg** trajectory
source (CoTracker3 + marker anchors + constant bias, IMU only inside tracking gaps), jaw label from the servo encoder,
quality gate GOLD + SILVER.

* **Training total = 197 episodes, 62,160 frames** (build finished 20:57): the gate kept 147 demos on 11-01 (56 + 33 +
  10 + 48); the dataset converter dropped 3 of them whose trimmed window inside the recording was shorter than 5 s
  (4.8 / 4.7 / 4.3 s: 145546 demo03, 154901 demo04 and demo12; this < 5 s rule is a standing converter rule applied to
  every set), so the 11-01 set `umi1101_CG_S05_gs147_train` has 144
  episodes; merged with the 53 of 10-30: `umi_CG_S05_gs197_train` (53 + 144). (A first 11-01 build at 20:40 dropped
  6 demos through a key-file concatenation bug; it was stopped and rebuilt. Counts from that partial build are not
  data.)
* **IK and masks.** With labels F (`--label fused`) and A (`--label rob`) the dataset builder sets the IK error to zero
  (`tag_rig_unsplit.py`, the line `if LABEL in ("rob", "fused")`), so `--ik-fail-mm` has no effect and no frame is
  masked because of IK: `umi1030_CG_S05_gold53_train` has 0 masked frames although 0.34 % (left) / 0.11 % (right) of
  its frames have an IK error above 30 mm. IK results are kept for QA (`ik_v1`, `ik_qa_stats`); IK matters only in that
  a demo on which IK fails entirely has no IK file and is not built.
* **Trajectory source: everything rebuilt from Cg.** A′ and Cg are trajectory sources (fusion variants), not label
  kinds; both were used with label F. A′ (fusion variant A + one xyz bias per demo and arm from the tag frames of the
  first 2 s) had NaN position spans inside some 11-01 demos (e.g. 152254 demo02 left, 47 % of the window); IK failed on
  4 demos, which were therefore dropped; the cause (fusion or bias step) is unknown. A′ had been chosen on 10-30 because
  on a hidden-marker comparison it beat Cg (absolute error 5.2 vs 6.5 mm, drift over 10 s 14 vs 22 mm; data owner,
  11-01). The two sources are never mixed.

## Test sets (never trained on)

* **P20** = P10 (10-30 take 150454: all 10 demos, not gate-filtered; the gate graded them 2 GOLD / 7 SILVER / 1 REJECT)
  + T10 (11-01 take 153036: 10 demos, 9 GOLD / 1 REJECT; demo07, the rejected one, was also dropped by the converter,

* Baseline: the E1000 DiT checkpoint at step 227795 (53 demos, trajectory source A′, label F) scores **19.89 mm**
  `val_score_mm` on P20 built from Cg (19.13 mm on P20 built from source A′). `val_score_mm` is defined in
  [`src/garment_pipeline/eval_deploy/tagrig_offline_eval.py`](../src/laundry_deploy/tools/offline_eval.py):
  the mean (not the median), over k = 16 and k = 32 and over the left and right arm, of the translation deviation in mm
  (position only).
* **Reject set:** every 11-01 demo the gate REJECTed, used for **gripper timing only** (the servo jaw labels are valid,
  the arm labels are not).

## Training

* Chain of the DiT fine-tunes on the RTX 4090 (via Ray; run scripts on the training node, data owner 11-01): a DiT
  pretrained for 100k steps on a 1 : 1 : 1 mix of Soft-Fold, iPhUMI and PrimeBot UMI (`DIT-MIX3-SF18IPH19PRIME20-PT100K`)
  → flattening GOLD-281, label F, 0.3× → pinching (10-29 set, 0.5×) → E1000 (10-30 set) → the 197-demo run below. The
  jaw BCE head (`GRIP_BCE=1`) and no gradient clipping (`GRAD_CLIP=0`) are environment options used only in this
  pinching chain from 10-29 22:30; the trainer defaults are an MSE jaw target and gradient clipping at norm 10
  (`src/garment_pipeline/training/dit_tagrig_v1.yaml`).
* E1000 (fine-tuned on the 53-demo 10-30 set, trajectory source A′, label F, 0.5×) was stopped at step 227795 (about
  725 epochs); its P10 score had plateaued at 17.1–17.7 mm since about 150 epochs.
* Started on 1 November (submitted 21:07, RTX 4090 GPU1 via Ray; run `DITFT-E1000F227795-U200CG-S05-B64ACC4-BCE-GSM-AUG-E500-NOCLIP`,
  485,625 updates planned, about 4.7 days at 1.2 steps/s; data owner, 11-01; no results yet): DiT fine-tune **from the E1000 227795 weights** on the 197-demo Cg set (`umi_CG_S05_gs197_train`; the run
  name still says U200CG), new optimizer and cosine schedule over 500 epochs (a fine-tune, not a resume), a checkpoint
  every 25 epochs, gradient clipping off, jaw BCE head, batch 64 = 16 × gradient accumulation 4, RTX 4090 via Ray.
* New train-time image augmentation (`aug_image` in `src/garment_pipeline/training/tagrig_common.py`): global camera
  ±4.5 % / 2°, wrist cameras ±8 % / 5° / 5 % zoom, brightness / contrast ±15 %, colour channel ±5 %.
* Every checkpoint will be evaluated on P20 (Cg) and on the reject set (gripper), and archived to the SSD.

## Robot runs on 1 November (qualitative; data owner, 11-01)

Not counted trials; no success or failure was scored. Two DiT checkpoints were run on the robot with the UI set to DiT,
commit 32, speed 1 (later 1.5), real-time-chunking look-ahead off (`nolook`):

1. the flattening fine-tune on GOLD-281 + 48 servo-labelled demos (label F, 0.3×, jaw BCE head): two runs of about 70 s;
2. the pinching baseline E1000 (53 demos, label F from trajectory source A′, 0.5×): one short run.

In both, the left jaw was mostly commanded open and the right jaw stayed closed. During the first run the left wrist
had one motor fault and the left arm once showed a command–measurement gap above 20°. Earlier robot runs (10-28 → 10-31):
which checkpoints, labels and speeds were used is not recorded.

## Robot and deploy changes on 1 November

* **Height calibration** (`src/garment_pipeline/eval_deploy/height_calib.py`): per-arm table plane from jaw-tip touches,
  robot FK vs. label frame. Left plane tilt 4.9° (+0 … −18 mm), right 2.6° (+13 … +3 mm). A UI checkbox adds dz(xy) to
  every committed row; the table stop uses the measured plane. Start-pose xy shift from touches on tags 400 / 401:
  left (+11, +14) mm, right (−3, +2) mm. A pivot fit of the TCP / joint offsets was rejected (the jaw tip is an edge; the
  fit was unstable); the kinematic configs are unchanged.
* **Fixed camera moved** since 10-26 (5–13 px, 0.5–1°); re-aimed to the 10-30 view (`cam_align.py`), residual about 5 px /
  0.4°. The re-aim adjusted only the angle; the camera height (113 cm, set by the raise of 10-25) was not re-measured.
* **Soft stop:** Space or the soft-stop button brakes on the current command without latching an E-stop; the hard E-stop
  button stays; safety stops still E-stop. READY unparks parked arms first and names an arm that refuses writes.
* Speed: UI maximum 2 (the S05 / S03 data is slowed); a speed above 1 caps the DiT commit at 32 / speed steps.
* **Left wrist connector** (j5 / j6 / gripper) dropped out twice; re-seated, bridge restarted with the same settings.
  During UMI recording the robot boards are unplugged.
