## 1. Deploy (6–7 November), now the code the robot Mac runs

- Since 11-06 the launchers in `~/laundry_dit_training/deploy` run this repository's `laundry_deploy` (same commands and
  flags; `DEPLOY_CODE=old` runs the earlier garment-pipeline code). Offline evaluation of one checkpoint (FLAT250 ep08,
  val stride 64, ≤ 3000 frames, CPU) gave identical output in the old and the new code.
- **Latency matching** (UMI style, 11-06): `tools.latency_probe` (elbow and jaw chirps through the bridge, cross-correlation)
  and `tools.cam_latency` (camera films a QR / blink of the host clock) write `latency.json`; UI setting `latency_match`
  sends arm and jaw commands ahead by the measured delay and anchors state / history at the head-image capture time.
  Measured 11-06: arm L 58 / R 64 ms, jaw L 173 / R 171 ms, cameras global 1.4 ms, left wrist 38 ms, right wrist 61 ms.
- **p_grasp on the robot** (`core.pgrasp`, 11-06): FLAT-PGRASP checkpoints get state 18, 19 from the robot. The frozen
  wrist-camera classifier gives P(held) 0.97 / 0.94 on the robot's closed, empty jaws (the robot jaw looks larger and
  glossier than the HandUMI jaw), so the default source is the jaw state (closed = 1, open = 0, same window rule);
  `DEPLOY_PGRASP_SOURCE=vision` runs the classifier.
- **Contact floor** (`core.contact`, 11-06): the MIT bridge returns joint torques (`tau_nm`); a torque-change detector
  near the table raises a per-arm floor. Built, then switched off by the user (setting `contact_floor`); 11-07 the run
  loop logs q / torque / commanded q per read (`qtau.npz`) for a gravity model first.
- **Joint-limit hold** (11-07): when IK is pinned at a joint limit and far from the target (`ik_hold_mm` 15, `ik_hold_deg`
  30), that arm holds its last accepted joints instead of going to a twisted closest pose; the solver margin is
  `lim_margin_deg` 3.
- Other: jaw open limits L 0.70 / R 0.79 (11-06 tip-gap match: 80 mm = HandUMI fully open); the READY move no longer checks
  TCP height along the joint path (user 11-06); the UI overlays use `robot_cam_v006` (v005 put the TCP 40–90 px off);
  rollout videos go to `~/Desktop/rollout_videos`.

## 4. Tag-free collection (11–12 November)

- 11-11 the user removed every AprilTag (both hand rigs and the table start tags 400 / 401). Start marks are now two black
  L tapes on the table; every demo starts with each hand unit resting on its L. The table was moved and put back.
- Tag-free mode of the pose chain (`scripts/laundry/tagfree/`, production snapshot): start seed from the L tapes and the
  resting units in depth, yaw from the IMU (Mahony) anchored by the L heading at rest, then the usual CoTracker → point
  solver → gate → fusion → labels. Two fixes found the same evening: the seed rotation was NaN before the trimmed demo
  start, and the rigid fit started 4–8 cm outward of the true body origin (seed now = L tape + rest rotation · offset).
- Check on a tagged take processed as if it had no tags (20261105_164113 → clone 164114): jaw-tip error vs the tag
  measurement left 40 → 17 mm, right 80 → 9–14 mm after the fixes, flat over demo time.
- 11-11 sets: train 29, val 7, test 4, silver 16, reject 4 (pilot take 121020 is test only). 11-12 (four takes processed
  so far): train 16, val 5, test 2, silver 12, reject 4; more takes in progress.
- 11-12 the Orbbec was re-aimed by hand after re-cabling; the residual is in `robot_cam_v007` (= v006 corrected by an ICP
  of the static depth scene against 11-11 takes; control pair 0.02° / 1.5 mm). Uncorrected, the error would have been
  6–27 mm in the workspace. Tools: `laundry_shared.visual_teleop.tools.orbbec_frame_server` + `laundry_deploy.tools.cam_align`.
